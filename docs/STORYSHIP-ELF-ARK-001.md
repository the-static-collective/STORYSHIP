# STORYSHIP-ELF-ARK-001 — A cold-boot carrier, not an agent

Status: **experimental transport adapter**. This file does not extend or reinterpret `storyship/packet/v0`, which belongs to the music-voyage event/replay constitution. Here the *passenger* is the attributable relation from one bounded ELF occurrence to material that may later seed another. The **artifact and original receipt bytes** are the carrier. An Ark is **not** a running ELF, a continuation of the first ELF's identity, an authorization grant, or a destination admission.

## Exact source and scope

This v0 recognizes only the bounded deterministic occurrence receipt from the [Workbench GENESIS-ELF-001 experimental PR #60](https://github.com/the-static-collective/static-workbench/pull/60), head `38c6b13747f62b70961b93a0124a06ebd2932f20`. It validates the source receipt's fixed field set, unadmitted status, producer class, and artifact digest consistency. It does **not** independently prove that Workbench actually produced the bytes, that the original ELF had been independently verified against its original seed/input, or that a prior claimed parent exists. Any source execution claim requires separate project-owned evidence.

`storyship/elf-ark/v0` is its own versioned transport schema; it is not a `storyship/packet/v0`, music-voyage launch receipt, general archive format, or a shortcut past historical-selector / human-GO / Haunted Phonography customs gates.

## Manual seal / verify / receive (Node.js >=22)

Start with an existing verified Workbench occurrence directory containing only `artifact.txt` and `receipt.json` (generated by `python3 -m static_workbench.elf_genesis hatch ...` and checked with its own `verify` command). **The Workbench `demo` uses a temporary directory and deletes it at exit; use `hatch` for a carrier you intend to preserve.**

From a checkout of this Storyship branch, choose a *new* directory on a **separately provisioned and mounted persistent carrier**. These commands do not discover, mount, format, partition, or select disks; check the destination independently:

```sh
node cli/elf-ark.mjs seal --occurrence /path/to/first-occurrence \
  --destination /path/to/persistent-carrier/ark-001

node cli/elf-ark.mjs verify --ark /path/to/persistent-carrier/ark-001
```

`ark-001` contains exactly `artifact.txt`, `receipt.json`, and `ark.json`. The manifest binds the artifact digest, exact receipt-byte digest, asserted origin identifier, declared source-parent digest, manual passage, unadmitted destination, and a Storyship-canonical Ark ID. Nothing auto-launches, admits, publishes, or mutates the source occurrence.

After a **separately witnessed shutdown and cold boot**, access the manually retained package on an appropriate trusted machine with this exact Storyship code available, and run:

```sh
node cli/elf-ark.mjs verify --ark /path/to/persistent-carrier/ark-001
node cli/elf-ark.mjs receive --ark /path/to/persistent-carrier/ark-001 \
  --destination /path/to/new-local-workspace
```

`receive` re-verifies the Ark, refuses existing targets, and writes four files to the new workspace: `input.txt`, `seed.json`, `parent-receipt.json`, and `arrival.json`. The new seed explicitly declares the previous receipt's byte digest as its parent and uses `copy` as a deliberately deterministic operation. `arrival.json` reports `elf_hatched=false`, `authority=none`, and `destination_status=materialized_unadmitted`. Each reception receives a fresh `arrival_occurrence_id` and an operator-host `recorded_at` timestamp; the time is a clock reading, not independent proof of transport or boot.

## New ELF, separately constituted

With the Workbench carrier module available on the receiving machine, deliberately choose a separate output parent directory. A receiver-local operator can run:

```sh
mkdir -p /path/to/new-occurrences
python3 -m static_workbench.elf_genesis hatch \
  --seed /path/to/new-local-workspace/seed.json \
  --workspace /path/to/new-local-workspace \
  --output /path/to/new-occurrences

# Replace NEW_ID with the printed new occurrence directory basename.
python3 -m static_workbench.elf_genesis verify \
  --seed /path/to/new-local-workspace/seed.json \
  --workspace /path/to/new-local-workspace \
  --output /path/to/new-occurrences/NEW_ID \
  --parent-receipt /path/to/new-local-workspace/parent-receipt.json
```

This is a new deterministic fixture occurrence, not the same ELF waking up, not an OpenManus execution, and not a LOADOUT authority handoff. `receive` never calls `hatch` itself.

## Proof boundaries and refusals

- A passing `verify` proves only **local package consistency and digest binding**, conditional on SHA-256 and this adapter's declared schema. The Ark manifest is not signed and does not authenticate a sender or establish how the original receipt was produced.
- A physical cold boot, external persistent mount, offline guest execution, storage recovery, or second-machine transfer requires an independent observed occurrence and receipt. Fresh-process automated tests simulate neither machine boot nor disconnected networking.
- A claimed earlier parent may remain unverified; this Ark preserves the declaration rather than constructing missing ancestry.
- Transported material cannot carry credentials, execution permissions, identity continuity, Vault admission, or project authority. This v0 accepts exactly the known deterministic receipt fields and rejects additional fields; it is not a general secret scanner.
- The adapter intentionally refuses symlinked payloads, oversized files, unexpected package contents, pre-existing destinations and overlapping source/destination directories. These are local path guards, **not** a security sandbox for an untrusted mount or a defense against a concurrent filesystem adversary.
- The first portable storage gate must use a disposable VM and an explicitly selected expendable/persistent volume. Never run an experimental OS installer against the primary Zorin disk.
- STATIC OS GENESIS-001 currently does not bundle the required Node.js 22 Storyship runtime. Use the adapter on a trusted host, or separately provision and verify a suitable guest runtime before claiming guest-native execution.

**Next gate:** independently boot GENESIS-001 in a VM, attach a deliberately provisioned persistent carrier, perform the complete seal -> power-off -> new boot -> verify -> receive -> new ELF sequence, and preserve externally witnessed results. Only afterward consider an exact-pinned, LOADOUT-authorized OpenManus worker. Do not promote passing fixture tests to that claim.
